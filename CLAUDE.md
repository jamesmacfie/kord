# CLAUDE.md

Kord is a local-first guitar chord practice app on TanStack Start, deployed to a
Cloudflare Worker. Read `README.md` for the architecture and `design.md` for the
locked design system before adding page-level UI.

## Commands

```bash
npm run dev                      # port 3000
npm run check                    # Biome lint + format
npm run test                     # Vitest
./node_modules/.bin/tsc --noEmit # types
npm run build
npm run deploy                   # build, then wrangler deploy
```

Run all four checks before you call work done. `npm run check` does not
typecheck, so `tsc --noEmit` is a separate step.

## Where things live

- `src/lib/music.ts` is the music-theory core: keys, qualities, CAGED voicing
  templates, progression templates, voicing scoring, practice-set generation.
  Everything else consumes it. Change it and you change the whole app.
- `src/routes/index.tsx` is the entire app shell, about 1,500 lines covering
  tabs, practice flow, settings, and progress. Split it only when a section
  earns its own file.
- `src/lib/practice-storage.ts` is the only place that touches browser storage.
  It tries IndexedDB, then localStorage, then memory. Keep persistence behind it.
- `src/routeTree.gen.ts` is generated by the router plugin. Don't edit it. Biome
  skips it.

## Conventions

- Import from `#/`, which `package.json` `imports` maps to `src/`. `tsconfig.json`
  also maps `@/`, which nothing uses. shadcn is configured to emit `#/`.
- Biome formats with tabs and double quotes. It covers `src/`, `vite.config.ts`,
  and `index.html` only, which is why the JSON config files use spaces.
- Add shadcn components with `pnpm dlx shadcn@latest add <name>`.
- Music theory belongs in `music.ts` with a test in `music.test.ts`. The suite
  covers the generation contracts, so a new quality, shape family, or
  progression template needs a case there.

## Gotchas

- The Cloudflare Vite plugin loads in production mode only. `npm run dev` never
  exercises the Worker, so test deploy-shaped changes with `npm run build`.
- The service worker registers in production builds only. When you change the
  cached app shell in `public/sw.js`, bump `CACHE_NAME` or returning users keep
  the stale shell.
- The repo carries both `package-lock.json` and `pnpm-lock.yaml`, and
  `pnpm-workspace.yaml` still holds placeholder values. npm is the working
  setup. Ask before switching.
